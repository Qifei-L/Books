## Positive controls

- Journal tax is split before validation; net and tax are posted in the same revision; edit regression test exists.
- SQL in report services is parameterized through SqlQuery interpolation; tenant scope stays in j.ledger_id.
- Class and location are ledger-scoped in writes and reads.
- Report filters use indexes on (ledger_id, class_id) and (ledger_id, location_id).
- Immutable revisions and effective-postings rules are unchanged.

## Verdict

The accounting core is stable enough for continued development, but this is not a production sign-off:

1. Fix the manual AR/AP authorization gap.
2. Finish State Charge and the tax-return direction mapping.
3. Add the class unique index and decide the document class FK policy.
4. Apply migrations and restart the API.
5. Add permission tests.

The next feature work (RecordSurface, M17 attachments) should start only after P0 items 1 and 2 are resolved or explicitly accepted as temporary.

## Fix log (2026-10-25)

- P0-1: manual AR/AP postings now require an organization administrator. The journal form hides control accounts from
  other editors. A non-admin editor regression test returns 403.
- P0-2: State Charge is a tax kind (state_charge), uses the other-tax sales line/account/print path and has a return
  category. The tax code form now includes the missing vat_input_non_deductible and state_charge kinds. Follow-up
  (2026-10-25): State Charge now has its own `state_charge_code_id` / `state_charge_amount` fields, its own posting
  line, print line and `t701_state_charge` return boxes; `other_tax_code_id` accepts only `other_tax` codes.
- P0-3: a manual VAT tax line carries its tax code and direction. The return maps it to line boxes and removes it from
  posting boxes so it is not counted twice.
- P1: classes now have a unique ledger/name index.
- P1: the class foreign-key decision is service validation only; class deletion is not offered, so no orphan path exists.
- P1: the tax_line migration defaults to false for existing rows; this branch is pre-release, so there are no historical
  manual tax lines to backfill.
- Remaining: report filter ids are not validated; report filters are not in the URL; the full-page RecordSurface and M17
  attachments are still open.

## Closing the P items (2026-10-25)

Everything listed as remaining above is now done on `feat/report-delivery`:

- Report filter ids are validated against the ledger (400 `INVALID_ARGUMENT`); filters live in the URL and are
  re-applied on refresh and Back.
- The full-page RecordSurface covers journal, sales invoice/credit note, purchase invoice/debit note and payment/
  receipt; the old journal/sales/purchase/payment detail and form dialogs are removed.
- M17 attachments are implemented (journal, sales and purchase records; 20 MB; safe types; audit; MCP).
- Manual AR/AP is no longer organization-admin-only: the ledger accountant/manager capability allows it, a bookkeeper
  does not, and the regression tests cover both.
- State Charge has its own sales-line fields and return boxes; the other-tax field rejects it.

Correction (2026-10-26): GDT has no State Charge tax. State Charge is an invoice label for VAT; the separate tax kind,
sales-line fields and return boxes were removed (`StateChargeIsVat`). The old `StateCharge` print label is the correct
one. See [Cambodia tax](04-cambodia-tax.md#state-charge-is-vat-2026-10-26).
- The class FK decision is documented (service validation, no deletion path); the `tax_line` flag has no historical
  rows to backfill on this pre-release branch.
- Playwright UI smoke tests cover the record surface, save/post/delete, deep links, Back and report filters.
